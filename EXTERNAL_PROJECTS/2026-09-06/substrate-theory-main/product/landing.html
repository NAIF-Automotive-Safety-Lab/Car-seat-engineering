// 02 — show me the code

Closed-form, in your terminal

One import, three derivations, zero free parameters

The substrate engine exposes derived quantities as ordinary Python calls. Each result is a closed-form expression in the six substrate primitives. There is no fit, no MCMC, no DFT inner loop — the cost is one floating-point evaluation.

Below: the QCD string tension (lattice-QCD reference: 0.18 GeV2), the universal BCS weak-coupling gap ratio, and the pion decay constant — each one expression on the substrate primitives.

  • Runs on a 2020 MacBook Air in <100 ms
  • No CUDA, no MPI, no proprietary licenses
  • Drop-in replacement for the prediction step in screening pipelines
python — substrate quickstart>_
# pip install -e ".[dev]"
from stiff_medium import hadron_mass_test as hm
from stiff_medium import bcs_gap_ratio_test as bcs
from stiff_medium import pion_physics

# Cornell string tension from K_pair=2, K_rank=5
sigma = hm.SIGMA_GEV2          # 0.180 GeV^2

# Universal BCS gap ratio: 2pi/e^gamma
ratio = bcs.universal_ratio()  # 3.5278

# Pion decay constant: f_pi = (1/2) * sigma * xi
fpi   = pion_physics.f_pi()    # 91.2 MeV

for name, val, ref in [
    ("sigma   ", sigma, 0.180),
    ("BCS gap ", ratio, 3.528),
    ("f_pi    ", fpi,   92.2),
]:
    err = abs(val - ref) / ref * 100
    print(f"{name} {val:>8.4f}  vs ref {ref:>7.3f}  ({err:5.2f}%)")

# sigma     0.1800  vs ref   0.180  ( 0.00%)
# BCS gap   3.5278  vs ref   3.528  ( 0.01%)

// 04b — the obvious questions

Honest answers to the hard questions

Is this a Theory of Everything?

No, and the engine doesn't claim to be. The operational claim is sector-by-sector closed-form prediction with explicit derivability tags. There are still active gaps — lepton hierarchy, CKM mixing, full Planck-scale UV closure, dark-matter quantification — documented in the open repo's "Open problems" section.

Has anyone independent reproduced this?

The code, tests, papers, and figures are public. Anyone with a laptop can clone and run pytest — that is independent reproduction. For citation-grade independent validation, my offer is straightforward: I'll co-author a methods paper with any group that wants to benchmark the engine against their incumbent tool in a domain.

What's the catch?

Substrate is strongest in QCD-scale mechanics, atomic/QED, gravity/EM hierarchy, and BCS-style condensed matter. It's weakest in lepton hierarchy, CKM/PMNS angles, Planck-scale UV closure, and the full nonlinear strong-field GR regime. If your problem lives in those weak sectors, I will tell you so on the intro call rather than sell you a pilot that won't work.

How does this fit alongside DFT / lattice / FEM?

It doesn't replace them — it pre-screens for them. Treat substrate as the cheap closed-form filter that decides which 1–5% of candidates deserve the expensive numerical run. Cluster spend drops; hit rate stays the same.

What if my problem isn't in the 30 disciplines?

Tell me about it. Many "missing" sectors are 1–4 weeks of substrate-extension work away (Category B). For some, the honest answer is "this needs an external anchor" (Category C) and we ship the engine with that anchor explicit. For some, the answer is "this isn't a substrate problem" and I'll point you elsewhere.

What does a 4-week pilot actually deliver?

Pilot week 1: scope & benchmark plan. Week 2: substrate calculation against your incumbent. Week 3: written report with A/B/C tags and speed/accuracy/cost benchmarks. Week 4: pilot-to-production transition plan + 1-hour wrap call. Everything in your repo, not in a black box.
